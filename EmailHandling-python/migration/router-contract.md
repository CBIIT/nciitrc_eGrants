## IO, configuration and failure contract

- **Settings and precedence (source):** `CommonUtilties/AppConfig.cs` loads required `appsettings.json` from the executable base directory, optional `appsettings.{DOTNET_ENVIRONMENT ?? Development}.json`, then `AddEnvironmentVariables` (`Section__Key` overrides JSON; config keys case-insensitive). If `DOTNET_ENVIRONMENT` is unset, overlay defaults to Development but `Router/Processor.cs` and `Router/Program.cs` omit the outgoing environment prefix; `DOTNET_ENVIRONMENT=Production` also omits it (case-insensitive); other nonblank values prefix `({value}) `. **DEBUG builds override `DOTNET_ENVIRONMENT` to `Development` in `Router/Program.cs` before `AppConfig.Load`**, including a value previously set to Production; this is a compile-time `#if DEBUG` behavior, not the `AppSettings:dBug` routing switch. Defaults `AppSettings:Verbose` and `AppSettings:dBug` are `n`; `FolderPaths:dirpathRouter` selects the source folder; `ConnectionStrings:EIM` is resolved after overlays. `RoutingBreakDuration` defaults to 1000 ms when missing, unparseable or containing case-insensitive `fail`; a parsed negative integer is not clamped and `Thread.Sleep` can fail. `GetConnectionString` expands `%VAR%`; missing required `DB_USER`, `DB_PASSWORD`, `EGRANTS_DB_USER`, `EGRANTS_DB_PASSWORD` throws, other absent placeholders expand to empty. `Router/GraphEmailService.cs` expands `%[A-Za-z0-9_]+%` in `Graph:ClientSecret`, then (only if blank) uses `GRAPH_CLIENT_SECRET`, then `Graph__ClientSecret` from process environment. Do not expose resolved secret, token or connection string in test failures.
- **Startup and Graph read (source):** `Router/Program.cs` constructs the processor; `Router/Processor.cs` `Process` connects OAuth first (`Router/GraphEmailService.cs` uses MSAL confidential client, tenant authority, client credentials and `https://graph.microsoft.com/.default`), opens SQL, navigates `FolderPaths:dirpathRouter`, then resolves child `Old emails` and loads **all** messages before processing. `GetFolder` treats `\` and `/` as separators; trims segments, resolves well-known roots by Graph ID or enumerates custom roots, then child folders via `$top=200` pages, matching `displayName` ordinal-ignore-case. Missing root/child fails before item processing. `GetEmails` starts `users/{mailbox}/mailFolders/{id}/messages?$top=200&$select=id,subject,body,bodyPreview,from,receivedDateTime`; follows each `@odata.nextLink` (also for folder enumeration), appends all `value` items with no 50-item fetch cutoff; uses nonblank `bodyPreview` as text body, else strips HTML tags; retains HTML body separately, uses `from.emailAddress.address` and parses receipt time or defaults to current local time. Original .NET follows absolute next links without a host/mailbox restriction; Python's same-mailbox/host restriction is an intentional security deviation, not a source invariant.
- **Graph writes (source):** `Router/GraphEmailService.cs` `Forward` constructs `OriginalMessageId`, default `FW: ` subject, original HTML/text. `Send` for forwards POSTs `/messages/{originalId}/createForward` with `{}`, parses returned draft `id`, PATCHes `/messages/{draftId}` with subject, ordered `toRecipients` (duplicates preserved) and `body: {contentType:"HTML", content: nonblank HtmlBody else TextBody else ""}`, then POSTs `/messages/{draftId}/send` with `{}`. A tagged branch overrides `FW: `; the Change of Institution branch overrides with untagged original subject. `MoveMessage` POSTs `/messages/{originalId}/move` with `destinationId` of `Old emails`; it occurs after all successful forwards. Administrative `SendEmail` instead POSTs `/users/{mailbox}/sendMail`, splits semicolon recipients, saves to sent items. Attachment retention by Graph `createForward` after body PATCH is **unresolved**; source code does not explicitly attach or clear anything. All HTTP GET/POST/PATCH failure paths throw with status, URL and **raw Graph response body** included in the exception; logging that exception may leak identifiers or sensitive response text. `Router/GraphEmailService.cs` `GetJson`, `PostJson`, `PatchJson` are evidence for this source exposure; target must not reproduce it. No secrets or raw response bodies in fixtures/logs.
- **Per-item failure (source):** `Router/Processor.cs` `Process` catches `HandleSingleEmail` exceptions (including failed sends/SQL/positional parse), logs, and calls `RaiseErrorToAdmin`. This creates **ONE** forward of the original via `/createForward` → PATCH → `/send`, with `LegacyErrorRecipient` **added twice** to its `toRecipients`; subject is `Error Occured! PROD eMailRouter vbs  >>(Subj: {original subject} )` plus environment prefix; body is the original HTML if nonblank, else text. The constructed error details are logged but `errorMessage2` is **not used as body** of that forward. When the alert succeeds, processing proceeds to move the original despite routing failure. When the alert fails, the uncaught exception escapes the per-item catch **before** the move, sleep and increment; later items may be skipped and the global handler runs. `failedToProcess` is set but never consulted. If move fails, `Process` sends a *new Graph sendMail* to `ErrorNotificationRecipients`, subject `[env prefix]Failed to move an item to old.`, body containing failure details; if this secondary alert succeeds, execution continues, sleeps and increments even though move failed; if it throws, processing aborts to global handler. Source: `Router/Processor.cs` `Process`, `RaiseErrorToAdmin`.
- **50-item threshold (source):** `Router/Processor.cs` `Process` sleeps then increments `itemsProcessedCount` once per completed loop body. At **count >= 50**, `EmailMe` sends one *new Graph sendMail* per completed item to `LegacyErrorRecipient`, including item **50** and item **51** (and every later item), subject `[env prefix]Warning! PROD eMailRouter vbs has processed 50 mail items in one instance!`, body `Hello Admin, 50 items have been processed in one instance and the application is now exiting. Please check whether there is duplicate items processing.` The body claims exit, but **there is no exit or hard cap**. If warning send fails, it propagates, interrupts remaining items and triggers global handling. No warning for count 49; 50 successfully completed items yield one warning, 51 yield two. An earlier failed alert that escapes the loop does not contribute to the count.
- **Global SMTP (source):** `Router/Program.cs` catches startup/process/global errors, attempts to reload config, then `CommonUtilties/SmtpEmailService.cs` sends HTML to semicolon-separated `ErrorNotificationRecipients` with subject `[env prefix]Global level email failure.` and exception details in body. SMTP defaults host/port/from/from-name, invalid port falls back to 25, `EnableSsl=false`, no explicit authentication (default network credentials configured), sends synchronously; failure of config reload, recipient parsing or SMTP send is caught and printed, not retried. `Program.Main` does not set a failure process exit code explicitly. **Credential risk:** source Graph errors and SMTP global body may contain sensitive exception text; the migration must redact and guard live logs/alerts, not replicate exposure.
- **Intentional safety deviations, not source parity:** current Python `app/graph.py` dry-run does not send/move but `--live` still performs OAuth, Graph reads and SQL connection (`app/main.py`); Python send mode leaves routing/send failures in place (does not move even on successful admin alert) and limits successful processing to 50 with one warning, while .NET may process 51+. Python rejects foreign-host/cross-mailbox `@odata.nextLink` whereas .NET follows it. `app/graph.py` redacts Graph HTTP errors. Test these policies separately; do not silently change them to satisfy a .NET parity test. Whether to retain them in implementation requires explicit operational approval. The source has **no dry-run mode**.
